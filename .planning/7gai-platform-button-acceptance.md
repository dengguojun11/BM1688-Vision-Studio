## 3. 质量门禁观察

本地训练报告示例显示：整体召回率 `0.9800`，训练质量通过；泛化、边端可用性待验证，发布状态为已阻断。该状态符合“训练指标不能替代 test 集、芯片转换和边端验证”的方案要求。

Provider 详情示例显示：目录状态为 `ACTIVE`，但运行时未注册，且错误为 `no executable adapter registered ...`。这说明界面已能揭示真实缺口，后续实现必须补可执行适配器和 HIL 证据，不能通过修改展示字段绕过门禁。

## 4. 后续工程任务（按优先级）

1. P0：实现 Provider 可执行适配器、注册/健康探测、HIL 证据和 Worker 作业闭环。
2. P0：实现模型优化器适配接口，生成带 SHA256、manifest、芯片/精度信息的真实 Bundle 制品，并接入发布门禁。
3. P0：接入边端 Agent 的难例反馈、审核、冻结数据集、自动训练和回滚链路，形成可审计账本。
4. P1：补分类、分割、检索等非 YOLO 训练 Worker；算法契约驱动参数表单和评测器选择。
5. P1：审计数据集版本查询的 N+1、分页和项目隔离；为关键按钮补 Playwright/API 联合测试。
6. P1：完成三视口、键盘、无障碍和首屏性能基线，逐步收敛旧兼容工作台入口。
7. P2：在 staging 完成迁移、备份恢复、Nginx 文档路由、权限、安全、性能和第三方回调验收后，才进入生产发布评审。

## 6. 本轮浏览器复核补充

- 训练中心三个标签均可切换；训练作业详情、自动训练计划详情、训练报告详情都能展示质量四层和关联深链。训练详情中的 `metrics`/`metrics_summary` 已改为结构化摘要，例如“整体召回率 0.9800”，不再把完整证据 JSON 直接铺满抽屉。
- Provider 的“运行探测”在未注册适配器时返回可识别的完成提示，状态仍保持“未注册”；“本地 HIL”在缺少可执行适配器时返回 HTTP 409，未绕过发布门禁。证据抽屉可看到 `no executable adapter registered` 原因。
- 部署中心创建发布会明确阻断：当前项目没有同时通过质量门禁且包含 READY 制品的模型版本，创建发布按钮保持禁用。
- 进化中心空数据下“生成训练批次”保持禁用；“重建聚类”可执行并提示反馈聚类已重建，但无边端反馈时不会伪造聚类或训练批次。
- 柔性工作流代码和后端均定义四类类型；重新构建并关闭固定类型下拉的虚拟化后，浏览器 ARIA listbox 已完整暴露“专家回流、模型阈值实验、模型优化、第三方回调”四项，并能显示各自参数。未提交任何工作流。
- 兼容工作台训练深链已补上有效 `taskId/jobId` 校验；列表加载后会自动打开对应训练作业详情，找不到或任务不匹配时只保留高亮，不请求无效任务。

## 7. 仍需排期的交互/功能问题

- 移动端训练作业表已在本地改为固定窄屏布局：390px 视口保留作业、状态、操作、详情四列，表格 `scrollWidth=clientWidth`，不再出现内部横向滚动；任务/算法/执行资源/创建时间按断点隐藏。
- 算法目录已拆分运行时与质量门禁语义：无质量门禁配置显示 `RUNTIME_READY`/“门禁未配置”，有质量门禁配置显示 `QUALITY_READY`/“门禁已配置”；算法目录不再把契约配置直接标为 `PUBLISHABLE`，实际模型发布仍由模型版本五类质量证据和 READY 二进制制品门禁决定。
- 数据接入来源下拉已统一为后端支持的 `UPLOAD/S3/RTSP/FILE/THIRD_PARTY` 枚举；数据源连接改为按当前项目加载的受控下拉，无可访问连接时明确禁用并提示配置入口。
- 数据集创建表单只有名称和描述，数据集版本、清单校验、评审、冻结仍在后续版本流程；当前空表单提交按钮可点，但点击后由必填校验阻断。
- 旧工作台深链已能自动开详情，但仍需继续减少新流程对 `/yolo-training` 兼容入口的依赖。
- 架构巡检确认训练列表仍存在旧 `/yolo-train-jobs` 与新 `/training/jobs` 双合同，自动训练计划/报告仍部分依赖兼容工作台和旧服务；计划表里的“合格任务 / 样本 0 / 0”与关联作业已有评估证据的场景存在统计口径差异，需要统一聚合接口和数据来源。
- 进化闭环目前跨审核、聚类、数据集、训练和发布多个域，仍缺少统一 Saga/幂等编排证据；这会直接影响“无人值守自我进化”的最终验收。

## 8. 本轮模型优化制品链修复

- 本地优化器现在强制选择模型版本下 `READY` 的 `pt`/`onnx`/`bmodel`/`rknn` 输入制品，并校验路径位于 `MEDIA_ROOT` 内、文件真实存在且 SHA256 一致。
- 优化成功后生成确定性 `bundle-manifest.json`，登记为 `artifact_type=manifest`，包含输入制品摘要、参数哈希、芯片/精度、工作流/作业 lineage；manifest 明确 `deployable=false`、`production_ready=false`。
- 模型发布和部署门禁已改为只接受 READY 的真实二进制制品，manifest 只能作为证据，不能满足发布或部署条件。
- 专项测试 `test_model_optimization_adapter.py` 4/4、模型版本专项 7/7 通过；上轮工作流/模型版本/部署/优化联合专项 28/28 通过。该修复仍属于本地实现，未提交、未推送、未部署。
- Provider SPI、HTTP 模拟器、Worker、运行时和启动注册专项 23/23 通过；但真实 Provider 仍必须显式配置端点、健康检查、镜像/工具链及 HIL 证据，不能用本地确定性适配器替代。
- 数据接入来源与数据源连接改造：前端接入作业表单使用统一来源常量，并调用 `/v1/datasources?project_id=...` 展示当前项目连接；组件测试 5/5 通过，真实浏览器确认五个来源选项可见、无数据源时连接控件禁用。
- 训练中心列表已增加响应式列策略：390px 视口保留作业、状态、详情和必要操作，任务/算法/执行资源/创建时间按断点显示，避免移动端必须横向滚动。`npm run type-check` 通过，训练与工作流前端测试 18/18 通过。
