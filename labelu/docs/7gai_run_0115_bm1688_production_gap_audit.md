# RUN-0115 BM1688 与生产闭环差距审计

## 1. 审计范围

按边端算法、模型产品、架构、测试和运维视角，对当前本地改造和生产目标进行只读审计。本轮不改生产数据、不连接 AICM/S3/BM1688、不提交代码。

## 2. 已确认的正确方向

- 编译边界正确：服务器完成 `PT -> ONNX -> BModel`，BM1688 只负责加载、推理和真机证据。
- 产品边界正确：登录用户只有标注人员、管理人员；不新增项目/业务空间；模型中心保留本平台下载目录和 AICM 模型 ID。
- 数据闭环方向正确：第三方 S3 问题样本进入回流，经过去重、预标注、人工确认、冻结数据版本后再训练。
- 执行隔离方向正确：训练、BM1688 编译和边端验证逐步拆出独立 Worker，旧路径只作迁移期兼容。

## 3. 阻断项

1. 尚无同版本 MySQL 双进程、锁等待、重启接管、备份恢复和 systemd 证据。
2. 尚无真实 TPU-MLIR、PT/ONNX/BModel 三精度构建、BM1688 加载/推理/P95/短稳和车牌组合模型证据。
3. 尚无真实第三方 `strategy-integration-s3-config` 页面配置对应的数据包导入、对象去重、坏图隔离、任务创建和首轮重训闭环。
4. 尚无真实 AICM 发布、AICM 模型 ID、本平台目录、下载禁止和专家回流样本对账证据。
5. 生产主流程必须明确“任务创建/上传 -> 选择预标注 -> 自动预标注 -> 人工接受/修改/拒绝 -> 标签契约校验 -> 冻结 DatasetVersion -> 训练”；未经人工确认的预测不得进入训练。
6. 模型证据必须绑定训练数据快照、校准集及校准集摘要、工具链/镜像摘要、固件/运行库版本、输入输出契约、标签顺序和包摘要。

## 4. 应降级或隐藏的内容

- R01-R10、队列租约、fencing、迁移链和 Outbox 属于研发交付附件，不是登录用户菜单。
- 算法、规则、Provider、数据集、导入等技术模块保留后端能力，但不向普通标注人员展示一级菜单。
- 项目/业务空间、设备发布、OTA、灰度、设备回滚不进入一期产品；历史对象只读兼容。
- FP32/FP16/INT8 是否全部编译由管理人员维护的目标精度档案决定；不能把置信度/NMS 参数和模型精度掉点混为一谈。

## 5. 开源二次开发治理

LabelU 基于 LabelU-kit 二次开发。后续生产放行必须补齐：上游仓库 commit、Apache-2.0 许可证结论、内部补丁目录、数据库迁移兼容、上游合并策略、CVE/SBOM、构建镜像摘要和版本恢复点。当前只记录为基线要求，未宣称已经完成。

## 6. 结论

当前是“本地 L1 的研发改造蓝图”，不是生产可用闭环。下一阶段应优先完成真实 MySQL/Worker、真实 TPU-MLIR/BM1688、S3 回流和 AICM 对账四类证据；没有这些证据，任何菜单或页面只能标记“建设中/不可用”。
