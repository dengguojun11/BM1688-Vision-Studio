# RUN-0250 模型中心编号防串与禁止回滚语义收口

层级：本地 L1（生产未变更）  
责任角色：R01 产品、R03 架构、R04 后端、R05 外部平台、R06 模型算法、R08 前端/UI、R09 测试、R10 运维  
工作包：WP3 模型编译与验证、WP4 模型发布、WP5 测试验收

## 1. 本轮结论

模型中心一期链路继续固定为：YOLO11 训练得到 PT -> 导出静态 ONNX -> TPU-MLIR 生成 FP32、FP16、INT8 三份 BModel -> BM1688 真机验证 -> AICM 发布 -> 本平台保留发布模型列表和最终模型包。

发布成功后的稳定模型编号使用 AICM `model_set_id`。该编号还会用于第三方专家回流定位原模型，所以同一个数字编号不能在不同 AICM 环境之间静默改绑。发现跨环境同号时必须返回冲突，由管理人员核对环境，不能让系统自动猜测。

一期没有模型回滚机制。模型已经被 AICM 或其他平台下载后，本平台无法收回；模型有问题时只允许管理人员停止本平台后续下载，再由标注人员或管理人员按原发布流程发布替代模型。历史 `hidden/revoked/is_public` 字段保留读取兼容，但不再作为页面可操作的“撤回模型”功能。

## 2. 角色和按钮边界

| 角色 | 可以操作 | 不可以操作 |
|---|---|---|
| 标注人员 | 查看模型列表、下载允许下载的模型、从模型发布页发起发布 | 同步 AICM 全量目录、修改第三方别名、停止或恢复平台下载 |
| 管理人员 | 标注人员全部能力；同步目录；维护第三方回流别名；停止或恢复平台下载 | 回滚 AICM 模型、收回其他平台已下载文件、把旧模型编号改绑到另一 AICM 环境 |

模型列表“停止本平台下载”必须经过居中确认弹窗。弹窗明确说明：该操作只禁止本平台后续下载，不会撤回 AICM 或其他平台已经取得的文件。恢复下载同样需要确认。

## 3. 实现内容

1. `register_published_model` 在写本地包和目录记录前校验 AICM 环境与模型集合编号；跨环境同号或既有绑定编号不一致时返回 `409`，不会覆盖旧目录、不会落入同号本地包。
2. AICM 目录同步复用同一编号校验；发现跨环境同号时整次事务失败关闭，既有目录不被改名或改绑。
3. 模型目录更新接口只保留展示名称和 `download_enabled`。传入 `status/is_public` 返回 `400`，提示使用下载开关并发布替代模型。
4. 下载开关继续使用 `expected_download_enabled` 条件更新，避免两名管理人员用旧页面值互相覆盖。
5. 最终模型包使用同目录原子“只安装一次”；并发进程只能复用相同内容，遇到不同内容时返回冲突，不能覆盖先写入的长期保留包。
6. 页面移除“活动/隐藏/已撤销”和“对外开放”的编辑控件；历史状态仅显示为“历史隐藏/历史停用”，不表达外部模型已被撤回。
