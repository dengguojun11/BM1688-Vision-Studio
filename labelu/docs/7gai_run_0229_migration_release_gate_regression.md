# RUN-0229 迁移、发布闸门与部署契约回归

## 1. 本轮目的

本轮把一期上线前最容易造成数据损坏或错误放行的条件固化为本地可执行门禁。重点不是执行生产迁移，而是证明在证据不完整时系统会停止：

- 正式 Alembic 迁移链必须只有一个可达的 `head`，未知父链或重复候选不能绕过校验；
- 去项目化后的数据表、执行租约、`worker_action`、运行时字段和索引必须与 ORM/迁移闭合；
- 生产数据库连接前必须有同版本 MySQL 沙箱的备份恢复、重复升级、`2/10/20/50` 并发和锁等待证据；
- 健康、就绪、版本和 OpenAPI 路径必须由后端返回 JSON，不能被前端单页回退页面接管；
- 训练、BM1688、边端验证和数据集导入 Worker 默认关闭，只有通过发布闸门后才允许启用。

## 3. 本地验证证据

本轮执行迁移、发布闸门、MySQL 预演输入校验、Nginx 路由和 Worker systemd 契约专项：

```text
78 passed, 144 warnings in 15.40s
```

覆盖内容包括：

1. 正式 Alembic 唯一 `head`、候选迁移父链和空库升级；
2. 去项目化表结构与执行租约字段/索引的闭包检查；
3. 备份恢复、重复升级、`2/10/20/50` 并发、锁等待和旧 fencing token 的证据格式及失败关闭；
4. MySQL 沙箱地址必须是本机、专用数据库名，禁止把 SQLite、远程地址或生产库当作演练对象；
5. Nginx 精确 API/健康路径不被 SPA fallback 接管；
6. 训练、BM1688、边端验证、实验数据导入 Worker 的 systemd 单元默认禁用，启用需要显式开关。

## 4. 失败关闭规则

- 迁移不是唯一正式链、候选父链未知、ORM 与迁移字段不一致时，部署闸门失败；
- 缺少备份恢复、重复升级、并发矩阵或锁等待证据时，不连接生产 MySQL，也不执行正式 DDL；
- 真实数据库不是明确的同版本 MySQL 沙箱时，fencing 演练拒绝运行；
- 健康/就绪/版本/OpenAPI 返回 HTML 或 404 时，视为部署路由错误，不能按服务健康放行；
- Worker 未完成真实环境、权限、重启接管和运行日志验证时，保持关闭，不因本地测试通过而自动启动；
- 迁移失败不得通过手工改 `alembic_version`、删除历史数据或跳过备份来“修复”。

## 5. 并发与生产边界

本轮只验证门禁逻辑和证据格式，未连接生产 MySQL，未执行正式迁移、备份恢复、在线 DDL、`2/10/20/50` 真实并发、锁等待或 Worker 重启接管。SQLite 和模拟输入不能替代生产 MySQL 证据，也不能证明真实恢复时间、锁行为或 Nginx 部署结果。

## 6. 验收等级与后续放行

本轮达到 **L1（本地可执行契约）**。达到 L2/L3 前必须由 R10 在同版本 MySQL 沙箱完成真实演练，由 R09 保存原始日志和摘要，再由 R03/R04 复核迁移父链、失败关闭和模型替代发布证据。已发布到外部平台的模型不做回滚；发现问题时只禁止本平台后续下载，并按新版本重新编译、验证和发布。用户明确“提交代码”后，才进入统一提交、备份、迁移、部署、两类账号浏览器验收和生产探针复核；在此之前不提交、不推送、不部署。
