## 关键事实和边界

1. `labelu/alembic_labelu/env.py` 对真正空库会按当前 ORM 白名单建表并 stamp 当前 head。该路径不是生产 `h7i8j9k0l1m2` 的历史结构，不能用于证明生产表、列、索引或外键已经存在。
2. `b2c3d4e5f6a7_add_data_source.py` 是已核对的祖先证据，且生产 73 表只读盘点已确认 `data_source` 存在。因此第04段不得把它作为新表无条件创建；生产实际列、字符集、默认值和索引仍须快照逐项对账。
3. 当前候选链的 SQLite 演练使用手写最小前置表，仅验证候选段之间的外键闭包和逆序降级，不能代表真实生产升级。候选第01至07段仍需按生产基线将“创建表”拆成兼容增补或明确跳过；第08段的既有表字段增补也需快照验证。
4. 本轮没有连接生产数据库、没有执行 MySQL DDL、没有修改正式 `labelu/alembic_labelu/versions`，没有提交、推送或部署。

## 验收结论

达到本地 L1 的是离线闭锁和候选内部演练，不是生产迁移。L2 之前必须取得脱敏生产快照表/列/约束/索引清单，完成 8 段逐表差异清单、空 MySQL 演练和快照副本升级；在此之前 U0B 保持阻塞，平台不得连接生产启动。
