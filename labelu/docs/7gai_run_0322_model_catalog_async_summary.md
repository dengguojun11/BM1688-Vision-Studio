# RUN-0322 模型中心列表与全量摘要异步拆分（2026-09-21，本地 L1）

## 1. 背景与生产证据

生产只读压测（RUN-0310）显示，模型中心列表 `size=1` 单请求中位约 1644ms，5 并发单请求约 8142–8674ms。原因不是当前页列表本身，而是列表接口为了返回顶部统计卡片，额外读取筛选范围内全部导出记录、训练作业和边端验证结果，并逐条构建质量门禁。

RUN-0311 的同进程 single-flight 只能合并同一时刻的重复计算；计算完成即释放，多进程/多副本仍会重复扫描，也没有结果缓存和失效版本。因此本轮不改变统计口径，不直接增加不具备失效策略的 TTL 缓存。

## 3. 关联逻辑

1. 页面请求 `/yolo-bm1688-exports?page=...&size=...&include_summary=false`，只返回当前页、总数和当前页详情。
2. 页面随后请求 `/yolo-bm1688-exports/catalog-summary`，携带同样的任务名称、数据集分类和编译状态筛选，返回 `total/running/blocked/publish_ready/pending_edge/failed`。
3. 统计请求失败时只显示统计暂不可用，当前页仍可查看、打开详情、评估、手动边端验证和下载。
4. 编译/边端轮询每 4 秒刷新当前页；全量统计至少 15 秒才重新取一次，避免后台任务进行时反复扫描历史记录。
5. 旧客户端不传 `include_summary` 时默认保持原行为，继续返回 `meta_data.summary`；新页面显式使用异步路径。
6. 摘要扫描以 500 条为上限分块，每个分块关闭重复总数查询，逐块累加统计；数据量变化时仍以列表请求的筛选总数作为最终 `summary.total`。

## 4. 当前限制与后续门禁

- 本轮仍保留逐条 Python 质量门禁计算，列投影和分块降低 IO、内存峰值和长事务风险，不能宣称已经解决所有全量计算耗时。
- 暂不增加进程内 TTL 结果缓存；多副本缓存必须绑定数据库数据版本/失效机制，并覆盖导出、训练质量和边端验证变更。
- 尚未在同版本生产 MySQL 上执行 `EXPLAIN`、慢查询、连接池、锁等待及 1/5/10/20 并发回放；不能把本地 42 个后端测试和 25 个页面测试当作生产性能验收。
- 生产部署、提交、推送和重启均未执行，等待用户明确“提交代码”。
