# RUN-0078 跨进程执行租约接管与旧Worker隔离

## 1. 范围

- 日期：2026-09-18，Asia/Shanghai。
- 目标：验证执行期租约依赖共享数据库状态，而不是进程内互斥；新Worker接管后，旧Worker的旧fencing token不能再写入。
- 角色与工作包：WP3边端验证；R03架构、R04后端、R07边端算法主责，R09测试验收。
- 不连接生产、不执行真实SSH/BM1688、不提交、不部署。

## 2. 受控跨进程场景

1. 进程A领取任务，获得`fencing_token=1`，租期30秒。
2. 进程B在模拟租期过期时间点领取同一任务，获得`fencing_token=2`并写入新状态。
3. 进程A随后使用旧token写入，条件更新返回`False`。
4. 最终共享数据库只保留进程B的状态、owner和token=2。

测试使用Python `spawn`启动两个独立进程和同一SQLite文件；时间点受控，验证的是跨进程共享状态和token隔离，不把SQLite锁等待结果等同于生产MySQL性能结论。

## 3. 页面、接口和数据影响

- 数据库正式迁移：无变化；执行期字段仍等待正式第08段生产迁移。
- 业务语义：接管者可以继续执行，旧Worker不能覆盖接管者结果；不引入模型回滚或自动召回已发布制品。
