# RUN-0151：边端难例去项目化落地

## 本次交付

边端问题图片可以不携带项目标识直接写入进化中心。系统将这类记录放到固定的 `global` 作用域，并记录创建者；历史记录仍保留原有 `project_id`，用于追溯和兼容旧客户端。

## 页面与接口

- `GET /api/v1/edge-feedback/hard-examples`：不传项目参数，进入全局难例列表。
- `GET /api/v1/edge-feedback/hard-examples?project_id=历史项目ID`：保留旧的项目筛选方式。
- `POST /api/v1/edge-feedback/events`：`project_id` 可不传；重复的 `事件标识 + 作用域` 或 `指纹 + 作用域` 仍然幂等。
- 列表、详情和复核响应继续返回 `project_id`，但它只是历史来源字段，不构成前端项目菜单。

## 两类用户权限

- 管理人员：可查询全部作用域的难例；可以复核无项目难例。
- 标注人员：可查询自己创建的无项目难例，以及自己拥有、创建模型或有效参与的历史项目难例；无项目难例不能由标注人员复核，统一由管理人员确认后进入训练队列。

## 关联逻辑

RUN-0151 本身不承诺主动学习聚类；随后 RUN-0152 已将聚类刷新改为按 `scope_key` 工作，无项目难例可以进入 `global` 聚类。历史项目难例继续使用 `project:<id>` 兼容链路。无项目模型版本可以作为来源记录，但不再被错误地判定为“模型不属于当前项目”。

## 数据库与并发

迁移 `z9c0d1e2f3a4_add_global_evolution_scope.py` 为两张边端表增加 `scope_key`、`created_by`，把历史项目行回填为 `project:<编号>`，允许 `project_id` 为空，并增加作用域级唯一约束和查询索引。写入仍通过数据库唯一约束兜底，并发重试返回已提交的同一条记录。
