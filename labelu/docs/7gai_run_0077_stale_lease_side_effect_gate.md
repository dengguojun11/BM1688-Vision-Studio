# RUN-0077 失租副作用前门禁与异常收尾保护

## 1. 范围

- 日期：2026-09-18，Asia/Shanghai。
- 目标：执行租约失效后，旧Worker不再发起SSH连接，也不继续执行远端日志拉取和清理。
- 角色与工作包：WP3边端验证；R03、R04、R07主责，R09验收。
- 不连接生产、不执行真实SSH/BM1688、不提交、不部署。

## 2. 发现的问题

执行链虽然在上传、远端脚本、回传和解析前检查租约，但SSH初次连接前没有检查。若Worker在样本包准备完成后刚好失租，旧Worker仍可能先连接设备。异常收尾的日志拉取和远端目录清理同样没有检查，可能在失租后继续产生副作用。

## 3. 实现决定

- 在`ssh_connect`调用前强制执行`_ensure_manual_execution_current`。
- 远端日志拉取前检查租约，失租时记录`remote_log_pull=skipped_stale_lease`。
- 远端成功清理或失败保留前检查租约，失租时记录`remote_cleanup=skipped_stale_lease`。
- 不改变失租任务的终态策略；旧Worker不写失败终态，交给新Worker/陈旧任务恢复流程处理。

## 4. 页面、接口和数据影响

- 页面、菜单、按钮、权限和HTTP接口：无变化。
- 数据库：不新增字段；只在执行摘要中记录跳过的收尾动作。
- 模型发布、下载控制和模型回滚策略：无变化。
