# RUN-0310 生产模型中心并发性能只读采样（2026-09-20）

## 1. 目标与边界

针对方案要求的“考虑并发性能瓶颈”，对生产模型中心列表接口做低频、只读采样。使用管理员令牌，只执行 GET，不创建任务、不触发编译、不改变配置。采样结果只代表当前线上版本，不能证明本地改动已经部署。

## 2. 单请求采样

请求均使用正确分页参数 `page=0&size=1`，每个接口连续请求 3 次：

| 接口 | 状态 | 3 次耗时（毫秒） | 中位数 |
|---|---:|---:|---:|
| `/api/v1/tasks` | 200 | 52、41、42 | 42 |
| `/api/v1/published-models` | 200 | 39、34、30 | 34 |
| `/api/v1/yolo-bm1688-exports` | 200 | 1799、1644、1560 | 1644 |

BM1688 导出列表即使只请求 1 条，仍明显高于普通列表接口。

## 3. 并发采样

对 `/api/v1/yolo-bm1688-exports?page=0&size=1` 发起 5 个只读并发请求：

```text
status: 200,200,200,200,200
individual_ms: 8674,8206,8302,8442,8142
total_elapsed_ms: 9458
```

这说明当前线上存在明显的并发排队或共享资源争用。不能以“全部返回 200”判定性能合格。

## 4. 本地代码路径核对

当前本地 `labelu/internal/application/service/yolo_bm1688_export.py:list_exports_global` 在分页查询后，当 `total != len(rows)` 时再次以 `size=total` 读取全部导出记录，并调用 `_summarize_export_catalog_rows` 对全部记录计算训练质量、边端状态和发布门禁。该路径与线上慢接口的表现一致，但生产数据库执行计划、SQL 耗时、连接池等待和文件读取耗时尚未取得，不能仅凭代码推断唯一根因。

## 5. 性能工作包要求

下一轮 R03/R04/R09/R10 必须在同版本预生产完成：

1. 用真实数据量回放列表页，分别测 `size=1/20/100` 和 1/5/10/20 并发。
2. 采集 SQL 计数、慢查询、连接池等待、锁等待和 Python 质量计算耗时。
3. 将列表页的页内数据和全局摘要拆分或改为数据库聚合/可失效缓存，禁止每次请求加载全量导出记录。
4. 保持摘要字段语义不变，并验证权限过滤、任务名称筛选、导出状态筛选和发布门禁计数。
5. 设定放行目标：单请求 P95 ≤ 1.5 秒，5 并发 P95 ≤ 3 秒；若真实生产容量不同，须在预生产基线中重新批准阈值。

## 6. 验收等级

本轮为 **生产 L0 只读性能证据**。没有修改代码、数据库或生产配置；性能优化、同版本 MySQL 回放和部署验证尚未完成。
