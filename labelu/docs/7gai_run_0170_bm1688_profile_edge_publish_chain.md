# RUN-0170 BM1688 Profile 摘要贯穿边端验证与 AICM 发布门禁

**日期**：2026-09-20  
**环境级别**：本地 L1（未提交、未推送、未部署）  
**对应工作包**：WP3 边端编译与验证、WP5 测试验收  
**责任角色**：R03 算法架构、R04 后端、R06 模型算法、R07 BM1688 边端、R09 测试；R10 运维协作

## 1. 本轮要解决的问题

RUN-0168 已经把 `BM1688Profile` 和 `profile_digest` 写入模型制品清单，但板端验证报告和 AICM 发布门禁还只核对旧的制品执行摘要。这样可能出现“同一个导出编号下，边端实际加载的编译档案与服务器清单不一致”的证据断链。

本轮只补证据链，不新增菜单，不在 BM1688 上编译，不引入设备发布、OTA 或回滚。

## 2. 已落地改动

### 2.1 服务器导出包

- Board Agent 和 SSH 两种验证包的 `run_config.json` 同时携带：
  - `bm1688_profile`
  - `profile_digest`
  - 原有 `artifact_execution_signature`
- 摘要由服务器根据导出清单中的 Profile 重新计算，不接受数据库中的旧摘要直接透传。

### 2.2 边端回传

- Board Agent 和 SSH 运行器将 `profile_digest`、`bm1688_profile` 原样写入验证回传 JSON。
- 板端继续只做 BModel 加载和推理，编译位置仍为服务器；未改变 BM1688 的运行职责。

### 2.3 平台证据门禁

- `edge_validation_evidence` 支持按本次导出清单声明期望 `profile_digest`。
- 摘要缺失：进入 `PARTIAL_COMPLETED/pending`，不能作为发布证据。
- 摘要不一致：进入 `fail`，禁止发布。
- 旧制品没有 Profile 清单时保留历史读取兼容；新制品只要存在 Profile，就必须完成摘要比对。

### 2.4 AICM 发布

- 模型中心发布列表增加 Profile 摘要门禁原因：`profile_digest_missing`、`profile_digest_mismatch`。
- 实际发布前再次读取导出清单和边端报告，摘要不一致或缺失直接返回错误，不创建 AICM 模型集。
- AICM `model_set_id` 仍只在外部发布成功回执后写回；本平台模型目录仍保留同一模型的下载记录。

### 2.5 Board Agent 与 SSH 的主次

- **主路径：Board Agent**。它部署在 BM1688 侧，主动从平台领取任务、下载验证包、加载 BModel、推理并回传结果；生产环境不需要平台主动进入设备，也不增加登录用户角色。
- **兜底路径：SSH**。用于人工排障、旧设备兼容和没有 Agent 的受控验证，不能绕过同一 Profile 摘要、固定评估集和发布门禁。
- 两条路径不是两套业务流程，而是同一边端验证契约的两种执行器；任何一条路径回传摘要不一致，都不能发布。

## 3. 本轮验收证据

| 验收项 | 结果 |
|---|---|
| 边端证据缺少摘要 | `pending`，包含 `profile_digest_missing` |
| 边端证据摘要不一致 | `fail`，包含 `profile_digest_mismatch` |

| Python 编译检查 | 通过 |
| `git diff --check` | 通过（仅有工作区既有换行提示，无差异错误） |

## 4. 角色验收边界

- **R03 算法架构**：确认 Profile 是服务器编译输入与边端证据的唯一版本摘要；确认历史无 Profile 制品不会被误判为新链路通过。
- **R04 后端**：确认摘要随验证包生成、回传、入库和发布门禁传递；异常状态采用失败关闭。
- **R06 模型算法**：确认 Profile 仍锁定模型族、输入输出、前后处理、工具链、校准集和类别顺序；本轮未改变算法阈值或精度标准。
- **R07 BM1688 边端**：确认设备只加载 FP32/FP16/INT8 BModel 并回传摘要，不执行 PT/ONNX/TPU-MLIR 编译。
- **R09 测试**：确认缺失、篡改、不一致和一致四类证据；覆盖 Board Agent、SSH、AICM 发布列表和实际发布硬门禁。
- **R10 运维**：确认本轮没有连接真实设备、AICM 或生产，不得据此开启 Worker 或放量。

本轮不代表生产完成。仍需在同一版本的真实环境完成：

1. 真实 TPU-MLIR 编译并核对三种 BModel 的输出节点、shape、精度和文件摘要。

4. AICM 测试账号上传成功后核对 `model_set_id`、本平台模型目录和第三方回流匹配。
5. 生产部署后重新执行 JSON 探针和退休写入口门禁。
