## 1. 核对结论

### 1.1 标注人员可以发布自己有任务权限的模型

- AICM 发布入口 `start_publish_job()` 和实际发布入口 `publish_to_aicm()` 均通过任务访问检查；任务创建者、有效协作者和系统管理员可以继续发布，非任务成员被拒绝。
- 模型仓库的 `ModelVersion.publish` 使用相同的任务访问判断，质量门禁、BM1688 三精度制品和边端门禁通过后才允许发布。
- 发布目录的编辑、同步、别名和下载开关属于全局管理动作，仍由系统管理员执行；这不影响标注人员发起其任务模型的 AICM 发布。

### 1.2 AICM 模型 ID、平台目录和本地包形成一条可追溯链

一次 AICM 发布成功后，系统按同一个 AICM `model_set_id` 建立以下关联：

```text
训练任务/导出记录
  -> yolo_bm1688_export.published_model_id
  -> published_model_catalog.public_model_id = AICM model_set_id
  -> published_model_catalog.aicm_model_set_id + aicm:<id> 兼容别名
  -> published_model_packages/<安全化模型ID>/model.zip
  -> ModelVersion.published_catalog_id，状态变为 PUBLISHED（存在对应 ModelVersion 时）
```

- 本地包落盘采用固定受控根目录，并保存大小、SHA256、MD5；已有不同内容的长期包不会被静默覆盖。
- AICM 模型目录同步会保留管理员设置的显示名、可见性和下载开关；远端不存在的记录只标记为不可用，不删除历史证据。
- 历史发布记录可能没有对应的 ModelVersion，仍可在平台目录中查询，但不能据此声称已经完成新的模型仓库血缘回链。

### 1.3 下载关闭使用乐观并发校验

- `/published-models/{catalog_id}` 只有系统管理员可以修改下载开关。
- 修改 `download_enabled` 必须携带页面读取到的 `expected_download_enabled`；数据库条件更新只在当前值未变化时成功。
- 缺少期望值或期望值过期均返回 `409`，不会静默覆盖另一名管理员的修改；成功修改写入结构化业务日志。
- 公共模型列表和公共下载接口同时检查模型状态、公开标记、下载开关和可用包；关闭下载后模型目录记录保留，但不能继续下载。

### 1.4 新发布写链不使用项目维度

- 新的模型发布、模型目录和平台下载接口不要求项目或业务空间；页面和请求不显示项目选择器。
- 服务层保留项目字段的历史读取兼容，用于读取旧发布 JSON 和旧任务记录；兼容字段不作为新记录的隔离边界，也不进入新的模型目录写入。
- 模型中心的权限边界使用任务创建者/协作者/系统管理员和全局目录管理员，不新增项目成员角色。

## 2. 本轮收口内容

- 强制下载开关更新携带 `expected_download_enabled`，补齐服务层和路由层的缺失值、过期值测试。
- 新发布写链去掉路由 `project_id` 参数，并停止向新发布记录写入项目字段；旧历史查询继续兼容读取。
- 补充模型发布目录回链、AICM ID 解析、平台内下载和项目字段不出现在新发布请求中的测试。
- 不新增一级菜单、角色、数据库实体或设备下发能力；平台内下载仍是已发布模型目录的受控能力。
