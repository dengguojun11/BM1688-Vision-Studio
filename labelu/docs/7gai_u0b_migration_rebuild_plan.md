# 7GAI 一期迁移后缀重建方案

## 1. 目的和边界

生产数据库当前 Alembic 版本为 `h7i8j9k0l1m2`，本地其后有 37 个未在生产执行的迁移。该 37 个迁移混入了已经取消的项目、组织、场景、设备发布、EdgeAgent、OTA、设备规则签名和模型回滚方向，不能原样上线，也不能再追加一个清理迁移。

一期迁移必须从 `h7i8j9k0l1m2` 重新建立唯一线性后缀。现有生产表和历史数据不做破坏性删除；新链只增加一期真正使用的表、字段和索引。迁移回退与模型发布回滚是两件事：模型发布没有回滚，问题模型只能人工禁止后续下载。

## 2. 八段线性后缀

| 顺序 | 迁移主题 | 保留内容 | 明确排除 |
|---|---|---|---|
| 01 | 数据与标签契约 | 数据集、不可变数据版本、复核、标签顺序、全量/单标签训练范围 | `project_id`、项目成员 |
| 02 | 算法与模型血缘 | YOLO目标检测、矩形框、BM1688、模型版本、制品、质量证据 | 31个未验证算法种子、第二套模型优化作业 |
| 03 | 内部执行基础 | 工作流、步骤、事件、Outbox、Attempt、调度租约、fencing token | 面向业务用户的通用工作流创建入口 |
| 04 | 导入与媒体资产 | S3/上传导入、媒体资产、分片上传、扫描和隔离 | 项目、组织、场景 |
| 05 | 问题样本与主动学习 | 第三方问题样本、去重、聚类、主动学习批次、数据版本血缘 | 设备回传作为唯一来源、设备发布状态 |
| 06 | 预标注与预测结果 | Provider、作业、预测集、复核、预标注投影 | 仅登记未接通的Provider |
| 07 | 三类业务规则 | 数据规则、模型规则、发布规则、不可变版本和版本审计 | 设备绑定、规则签名、设备回报 |
| 08 | 兼容字段与索引 | Task、附件、数据源、BM1688导出、专家回流的nullable关联和在线索引 | 全表同步回填、项目字段 |

第一段的 `down_revision` 固定为 `h7i8j9k0l1m2`，后续每段只有一个父版本。新链不允许合并节点和多 head。

### 2.1 当前22张项目外键表的唯一归属

以下清单由`phase_one_migration_plan.py`维护，并由专项测试与ORM外键闭包逐项比对。表只能属于一个迁移段；新增、遗漏或重复归属均直接失败。

| 迁移段 | 当前需移除项目外键的表 | 数量 | 实施说明 |
|---|---|---:|---|
| 01 数据与标签契约 | `dataset`、`dataset_version` | 2 | 当前 ORM 仍保留历史 `project_id` 外键；第01段必须在非空快照上完成无损移除，空库则直接创建无项目结构 |
| 02 算法与模型血缘 | `yolo_train_job` | 1 | 训练作业改用任务、冻结数据版本和创建人血缘；`model_version`已经无项目外键 |
| 03 内部执行基础 | `auto_training_plan`、`workflow_instance` | 2 | 内部执行以任务/数据版本/聚合对象定位，项目不再作为租约或幂等范围 |
| 04 导入与媒体资产 | `ingestion_job`、`media_asset` | 2 | 导入幂等按来源连接和外部包ID；媒体按摘要去重 |
| 05 问题样本与主动学习 | `inference_event`、`edge_hard_example`、`feedback_cluster`、`active_learning_batch` | 4 | 以AICM模型ID、发布目录ID、数据集版本和样本指纹关联 |
| 06 预标注与预测结果 | `provider_job`、`prediction_set`、`prediction_set_review_audit`、`prediction_set_projection` | 4 | 以任务、Provider作业和预测集作为边界 |
| 07 三类业务规则 | `rule_template`、`rule_binding`、`rule_binding_audit`、`rule_version_audit` | 4 | 规则按规则类型、版本和业务对象生效，不再绑定项目或设备 |
| 08 兼容字段与索引 | `task`、`data_source`、`strategy_task_integration`、`third_party_call_audit` | 4 | 对生产既有大表采用nullable兼容、分批对账和在线索引，不做迁移内全表同步回填 |

总计22张，与当前 ORM 闭包诊断完全一致。RUN-0162 已在 SQLite 非空历史行上验证第01段候选保留列、索引和行数；RUN-0163 已在本机 MySQL 沙箱验证候选的重复执行和历史行保留。已退休但不在一期白名单中的`project`、`project_member`、部署、Agent、OTA等表不进入这22张清单；它们在生产仅保留历史只读数据，不因新链升级而删除。

### 2.2 当前不能直接落首段迁移文件的原因

当前本地迁移目录仍有生产基线之后的37个未跟踪迁移，唯一head为`z3a4b5c6d7e8`。如果此时新增一个以`h7i8j9k0l1m2`为父版本的“首段”，会立即产生第二个head；如果挂在当前head之后，又会让生产依次执行已判定不可上线的37个迁移。因此本轮只固化表级归属和自动检查，不制造伪迁移。

实际重建顺序固定为：先完成37个旧文件的保留证据与新八段内容对照；再由R03/R10在独占窗口将旧后缀移出正式`versions`目录，生成以生产基线为父版本的八个新修订；随后立即执行唯一head、空SQLite、空MySQL和生产快照副本升级。完成替换前应用继续禁止连接生产库启动。

**基线真实性闭锁（RUN-0071）**：`env.py`对真正空库会按当前ORM白名单建表并直接stamp当前head，这只能验证空库引导，不能证明生产`h7i8j9k0l1m2`的历史结构。候选链不得用空库bootstrap或手写最小前置表替代脱敏生产快照；候选声明创建快照已有表时必须阻塞，先生成逐表列、约束、索引、字符集和行数差异。当前已由祖先迁移`b2c3d4e5f6a7`和生产73表只读证据确认`data_source`存在，其余对象仍需真实快照对账。

### 2.3 生成前离线闸门

重建不再依赖人工数文件。`phase_one_migration_rebuild_audit.py`显式登记生产基线后37个旧修订的处理决定和涉及对象：25个修订由八段新链替代，12个已取消方向整体排除。任何新增旧修订、漏登记、空对象清单、非法段号或“排除修订仍指向替代段”都会使审计失败。

在正式`versions`目录之外准备候选迁移，例如`.tmp/phase-one-rebuild/versions`。生成八段后执行：

```text
python -m labelu.scripts.audit_phase_one_migration_rebuild \
  --replacement-versions .tmp/phase-one-rebuild/versions
```

审计器只通过AST读取`revision`和`down_revision`，不会导入候选迁移、执行`upgrade()`或连接数据库。候选目录必须满足：

1. 只有8个迁移文件，修订标识依次为`gai_p1_01`至`gai_p1_08`。
2. `gai_p1_01.down_revision`严格等于生产基线`h7i8j9k0l1m2`。
3. 后续每段只有一个字符串父版本并指向前一段；元组父版本、动态父版本和合并节点全部拒绝。
4. 最终head只能是`gai_p1_08`。通过离线结构闸门后，才能把候选链送入空SQLite、空MySQL和生产快照副本执行级验证。

现有正式迁移目录保持不变，因此该检查不会产生第二head，也不会让应用误执行候选迁移。

## 3. 关键数据契约

### 3.1 数据与训练

- `dataset` 以 `owner_id`、`created_by`、`updated_by` 表达权限，不保存项目编号。
- `dataset_version` 只属于一个数据集，冻结后清单、样本范围、标签顺序和训练范围不可修改。
- 训练范围使用 `FULL` 或 `SUBSET`；选择单个标签时保存有序 `label_ids` 快照，不能通过运行时标签名称猜测。
- 历史空训练范围由应用解释为全量，不在生产迁移中锁表执行全量更新。

### 3.2 模型、编译与真机验证

- `model_version` 关联算法、数据版本、训练作业和父模型版本，不保存项目编号。
- PT、ONNX、FP32 BModel、FP16 BModel、INT8 BModel是同一模型版本下的不同制品，不是五个业务模型。
- `model_quality_evidence` 可关联具体 `artifact_id`，三种BModel分别保存转换和真机证据。
- 复用现有 `yolo_bm1688_export`，只增加nullable `model_version_id`；不新增第二套模型优化状态机。
- BM1688制品由编译服务器使用锁定版本TPU-MLIR生成，再通过现有SSH或板端主动拉取通道执行统一真机验证；不在板端编译，不建设设备发布Agent或OTA。代码内部现有`board_agent`只作为真机验证执行程序兼容保留，不承担模型下发、设备版本切换或回滚。
- 自动编译/边端验证派发使用独立的`queue_lease_owner`、`queue_lease_expires_at`短租约字段；它们只负责调度器交接，不能与边端实际执行的`lease_expires_at`混用。八段迁移必须为`yolo_bm1688_export`和`yolo_edge_validation_job`增加nullable字段及状态/到期索引，旧数据按NULL兼容。

### 3.3 第三方回流

- 导入幂等键为“来源类型 + 来源连接 + 外部数据包ID”。
- 媒体去重以文件摘要为主，不再按项目隔离重复文件。
- 问题样本必须保存外部数据包ID、AICM模型ID、本平台已发布模型目录ID、对象地址、摘要、事件类型和去重指纹。
- 设备编号只能作为可选来源信息，不能成为任务创建、数据集或模型匹配的主键。

### 3.4 规则与内部执行

- 规则类型固定为数据规则、模型规则、发布规则；规则版本发布后不可修改。
- 工作流实例只供S3导入、预标注、训练、编译、验证和发布链内部创建。
- Outbox领取、Attempt和租约必须支持原子领取、超时接管和fencing token，避免多进程重复执行。
- 编译和边端派发同样必须先条件UPDATE领取短租约，领取失败不得启动线程；提交异常按租约所有者释放，执行期仍由编译/板端Worker自己的状态和fencing负责。

## 4. ORM和空库引导

只替换Alembic迁移不够。当前空库会直接执行 `Base.metadata.create_all()`，因此取消的表仍会被创建。U0B必须同时完成：

1. 保留业务模型移除`project_id`和对`project`表的外键。
2. 历史只读的项目、组织、场景、设备发布、Agent和OTA模型标记为一期遗留表。
3. 空库引导只创建`phase_one_schema.py`显式一期白名单，跳过遗留表和未来未经评审的新ORM表；生产已有遗留表继续可被管理人员只读审计。
4. `env.py`、`run_migrate.py`和应用`init_tables()`复用同一个建表函数，避免形成三套空库规则。
5. 共享模块提供外键闭包诊断；在所有一期业务表移除`project`外键后启用严格硬门禁。测试库可按专项需要创建遗留表，但一期空库验收必须断言遗留表不存在。

截至 RUN-0160，`model_version` 已经在 ORM 中移除项目外键；闭包专项仍发现 22 张一期业务表保留 `project` 外键（新增确认 `dataset`、`dataset_version` 属于第01段）。这 22 项必须逐段纳入八段重建链处理，不能通过扩大/缩小空库白名单掩盖，也不能追加第38个清理迁移。

## 5. 37个旧迁移处置摘要

- 整体排除：项目/成员、设备发布、部署审计、Agent/OTA、组织/场景、设备规则签名、设备签名回报、向现有对象增加项目字段、第二套模型优化作业、31能力虚假种子。
- 保留重写：数据集与版本、算法与模型血缘、内部工作流/Outbox、第三方问题样本、标注复核、主动学习、媒体导入、Provider与预测集、三类业务规则、数据标签契约。
- 部分保留：自动训练只保留数据版本血缘；回流和第三方审计不增加项目字段；规则中心只保留模板、版本和审计。

逐修订映射以实施台账 `RUN-0010`、`RUN-0030` 和本轮迁移审计证据为准。旧37个文件在新8段迁移通过空库、生产快照副本和唯一head验证前不删除。

## 6. 性能和上线约束

- 大表变更按“加nullable列、在线建索引、分批补数据、最后加约束”执行。
- MySQL设置短元数据锁等待；超时立即中止，不在业务高峰自动重试DDL。
- 禁止在迁移中引用可变应用常量或执行全表同步更新。
- 必须记录每个ALTER耗时、元数据锁时间、接口错误率和慢查询。
- 生产接入新流量后不执行删除新表的downgrade。故障处理采用停止新写、兼容应用回退或前向修复；严重故障从升级前快照恢复到独立实例后切换。

## 7. 验收条件

1. 迁移图只有一个head，旧37个修订不再出现在新后缀。
2. 空MySQL和空SQLite均可完成一期建库，且不出现项目、组织、场景、Deployment、Agent、OTA和设备规则签名表。
3. 生产快照副本从`h7i8j9k0l1m2`升级成功，表、列、索引、外键、字符集和行数对账通过；RUN-0163 的本机 MySQL 沙箱证据不能替代该条件。
4. 所有一期新增业务表均无`project_id`。
5. 任务创建、标签契约、全标签/单标签训练、PT、ONNX、三种BModel、SSH真机验证、AICM发布、本平台下载和禁止下载完整回归。
6. 真实格式S3包重复通知只创建一个导入作业，同一图片只产生一条有效问题样本，并能按AICM模型ID关联本平台已发布模型。
7. 并发测试覆盖Outbox领取、租约接管、fencing token、Provider请求、S3包和问题样本去重、主动学习不重复选样。
8. 以上证据未完成前，U0B不得超过L1，平台不得部署到生产。
