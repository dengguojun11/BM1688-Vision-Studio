# RUN-0340 标签库允许修改英文系统值（2026-09-21，本地）

- 责任角色：R01 产品、R03 架构、R04 后端、R08 前端/UI、R09 测试
- 工作包：WP0、WP2、WP4、WP5
- 需求：管理人员可以在“系统管理 → 标注与数据治理 → 标签库 → 编辑”中修改标签的英文系统值；标注人员不获得全局标签库维护权限。

## 先行核验结论

- `AnnotationLabel` 是全局标签主数据，英文值由 `label_value` 保存，`normalized_label_value` 全局唯一。
- 任务契约、数据集标签契约、训练作业和发布模型均保存自己的标签快照或类别清单。因此不能用新英文值回写历史数据，否则会破坏旧模型的类别映射和第三方回流对齐。
- 修改标签主数据后，只有后续新建任务、后续新建契约和后续训练读取新值；已冻结数据版本、已完成训练作业、已发布模型和发布记录保留生成时的旧值。
- 后端已有版本号乐观锁和审计日志，本轮复用，不新增第二套标签版本表。

## 本轮改动

1. 后端 `UpdateAnnotationLabelCommand` 增加可选 `label_value`，复用创建时的英文格式校验。
2. `system_labels.update_label()` 在事务内校验新值全局唯一，同时更新 `normalized_label_value`，保持标签 ID 不变、版本号加一并写入审计前后值。
3. 前端标签编辑弹窗启用“系统值（英文）”输入框，编辑提交 `PATCH /v1/annotation-taxonomy/labels/{id}` 时携带新英文值。
4. 弹窗和保存成功提示明确说明：历史冻结数据、训练作业、发布记录和模型文件不会被重写。
5. 页面仍使用中文、居中弹窗和既有颜色唯一校验；没有增加项目/业务空间、设备发布或模型回滚入口。

## 并发与历史兼容

- 并发修改同一标签：第二个请求使用旧 `version`，返回 `409`，必须刷新后重试，避免静默覆盖。
- 并发修改为同一个英文值：事务内查询加数据库唯一约束双重防护，冲突返回 `409`。
- 旧任务仍引用旧英文值时，按任务契约快照和已保存配置继续运行；不会因为标签库改名而改变旧训练类别。
- 新任务如需沿用旧英文值，应在标签库中保留一个未占用的旧值或通过已有外部别名机制处理，不通过修改历史模型文件解决。
